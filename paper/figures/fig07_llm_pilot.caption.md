English caption

Pilot comparison of a fixed script, generic Pi, and the domain agent on four task types with two independent session repeats each (24 trials; eight per method). The two LLM conditions use the same qwen3-vl-plus model, tools, task prompts, permissions, backend parameters, and budgets; their system prompts differ. The script consumes structured task specifications. (a) A counts completed mapping work under the archived execution criterion (8, 7, 6); P applies the prespecified structured task-delivery scoring (8, 5, 6); T additionally requires no issue in the post hoc text-report audit (8, 5, 5). All counts use a denominator of eight, and T is a separate additional analysis. (b) Every original trial is shown with filled/empty cells denoting pass/fail for A, P, and T. Map, Backend, Recover, and Read denote ordinary mapping, a specified backend, recovery from a missing input using a provided alternative, and artifact-based reporting of validation boundaries. Amber outlines mark four provider/service-error trials; they remain in the denominator, including a generic-Pi trial that completed mapping before a service error prevented delivery. No trial was removed or rerun. Tasks end at mapping, so the pilot does not evaluate simulation or energy analysis; two repeats and four task types do not support a superiority or generalization claim.

中文说明

固定脚本、通用 Pi 和领域智能体的初步实验：四类任务，每类使用两个独立会话重复，共 24 次，每方法 8 次。两种 LLM 条件使用相同 qwen3-vl-plus 模型、工具、任务提示、权限、后端参数及预算，仅系统提示不同；固定脚本接受结构化任务规范。A 为历史执行判据下的映射完成数，依次为 8、7、6；P 为预先定义的结构化任务交付评分，通过数为 8、5、6；T 在此基础上追加事后文字报告审计，通过数为 8、5、5，作为单独的追加分析。全部指标分母均为 8。逐次小格中，实心/空心分别表示对应评分通过/未通过；Map、Backend、Recover、Read 分别为普通映射、指定后端、使用已给备用路径恢复缺失输入，以及读取产物并准确说明验证边界。黄色外框表示 4 次提供方/服务异常，全部保留，包含一次映射已经完成但交付前遇到服务错误的通用 Pi 试验。没有剔除或重跑失败。所有任务止于映射，不评价仿真或能耗分析；四类任务、两次重复仅支持 pilot 描述，不能声称领域智能体具有总体优越性或泛化能力。
